# UDS 画面テスト仕様書 ケース抽出ブリーフ（全エージェント共通）

## 目的
UDS（uds-web、FuelPHP 1.7 / PHP 5.6）を Laravel へ移行する。移行後の回帰確認に使う「画面テスト仕様書」（手動で行う画面単位のテスト）を作る。
**期待結果は「現行の動き」**（画面定義書に書かれた今の挙動）にする。移行後の環境で同じ動きになるかを確かめるための基準である。

## 入力
- 画面定義書: C:\Users\a-nozawa\USENDOC\UM_GRS_SGS整理\doc\04_現仕様\UDS\画面定義書\（00_索引.md に権限表・ユーザー区分・横断の要確認 Z-1〜Z-15）
- 担当ファイルは個別の指示を参照。画面詳細には「オブジェクト定義／データ定義／操作・イベント／バリデーション・エラー」の4表がある。ここからケースを起こす。
- 担当ファイル以外は必要な箇所だけ読む（全文を読み込まない）。

## ケースの作り方
- 「観点（concept）」単位でまとめる。1観点＝1画面（またはその画面の1つの側面。例: 検索条件／一覧表示・ソート・ページャ／更新処理／CSV取込）。1観点のケースは3〜25件が目安。ダイアログ・処理のみ・CSV出力・Ajax も、親画面の観点に含めるか独立した観点にする。
- 1観点の中の全ケースは、同じ「条件列」と「期待結果列」を持つ表になる。条件列は1〜3列（例: 「入力値」「データ状態」）、期待結果列は1〜3列（例: 「画面の表示」「操作・遷移」「DB・出力」）。列名は観点ごとに適切に決める。
- 区分 kind は3つのどれか:
  - 「正常」: 想定する利用・状態（0件表示、ソート、状態による表示切替なども正常）
  - 「バリデーション」: 入力チェック・業務条件の不成立（必須、形式、桁、存在しないシリアル、ステータス不一致、CSVの列数違い 等）
  - 「異常」: 権限なし（403）、未ログイン、他ユーザーのロック、二重送信、ファイル不正、存在しないID、外部連携失敗 等
- 重要な観点: 権限（ロールごとに開ける／403）、検索条件それぞれの効き方、0件・nosearch表示、ソート、ページャ、更新処理のDB更新内容（ステータスコードの遷移）、CSV取込のエラー行、CSV/Excel/PDF/ZIP出力の中身、フラッシュメッセージの原文、ロック（10分）、ダイアログの遷移。
- エラーメッセージは画面定義書の**原文どおり**に「」で書く。
- 既知の問題（画面定義書の「要確認」、索引の Z-1〜Z-15）に関わるケースは、期待結果は現行の動きで書き、`known` に「Z-7」などの番号（索引にない場合は「02要確認-3」のようにファイル番号＋その表の番号）と、`should` に本来あるべき動きを書く。
- 定義書で「要確認」「不明」の挙動は、期待結果を断定せず「（要確認）」を付ける。
- コードに書かれていない推測でケースを作らない。定義書から読み取れることだけにする。
- 文体: 簡潔な日本語。条件・期待結果のセルは短く（〜40字目安）。詳しい内容は prep / op / detail に書く。

## 準備データ・ロールの共通ID（必ずこれを使う）
| ID | 内容 |
|---|---|
| ROLE-ADM | admin（user_div=1）。ログイン後 /manage/master/device |
| ROLE-CEN | center（user_div=2）。所属センター＝センター南港 |
| ROLE-BRA | branch（user_div=3）。管轄＝支店A |
| ROLE-EXT | external（user_div=4）。管轄＝支店A |
| ROLE-CP | cp（user_div=5）。管轄＝支店A |
| ROLE-JIM | jimu（user_div=6） |
| ROLE-HSU | hoshu_itaku（user_div=7）。管轄＝支店A |
| ROLE-GUEST | 未ログイン |
| ROLE-OTHER | 同じロールの別ユーザー（ロック確認用） |
担当グループ固有の準備データ（依頼・端末・SIM・CSVファイル等）は、`prepData` に **担当プレフィックス付きID**（例: DATA-CEN-REQ1、CSV-DEV-NEW-OK）で定義し、ケースの prep から参照する。具体的な値（ステータスコード、種別、件数など）を書く。
