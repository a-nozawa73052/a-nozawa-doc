# 画面テスト仕様書の生成ファイル

`../画面テスト仕様書.html` を作るためのファイル一式。
仕様書を直すときは、HTML を直接編集せずに JSON（またはスクリプト）を直して、作り直す。

## ファイル

| ファイル | 内容 |
|---|---|
| `json/01〜05.json` | テストケースの元データ（正本）。画面定義書の 01〜05 に対応し、1 ファイルに 1 つ以上の画面グループが入る |
| `gen_screen_test.py` | JSON から HTML を作るスクリプト。目次、観点一覧、環境選択、絞り込み、ページ内検索、結果の保存と出力もここで組み立てる |
| `ref_style.css` | 見た目のスタイル。参照フォーマット（screen_unit_test.html）から抜き出したもの |
| `url_map.json` | 画面 ID → [画面名, URL] の対応表。画面定義書から作り、一部は手で補正した（SIM-15 など） |
| `BRIEF.md` | JSON を作るときの指示書。JSON の形式、ロール ID、書き方の決まりが書いてある |

## 作り直し方

Python 3 で実行する（標準ライブラリだけを使う）。このフォルダで次のように実行する。

```bash
python gen_screen_test.py json ref_style.css ../画面テスト仕様書.html url_map.json
```

- 終わると、件数（グループ数・観点数・ケース数など）が表示される。JSON の形が不正なときは、エラーの一覧を表示して止まる。
- `doc/04_現仕様/UDS/画面テスト仕様書.html` にも同じファイルを置いている場合は、作り直したあとでコピーし直すこと。

## JSON の形（1 ケース）

```json
{ "kind": "正常 | バリデーション | 異常", "name": "ケース名", "role": "ROLE-BRA など",
  "conditions": ["条件列の値", "..."], "expected": ["期待結果列の値", "..."],
  "prep": "準備", "op": "操作", "detail": "詳細な期待結果",
  "known": "既知の問題の番号（Z-7 など）", "should": "本来あるべき動き" }
```

- `conditions` と `expected` の数は、観点の `conditionColumns` と `expectColumns` の数に合わせる。
- 詳しくは `BRIEF.md` を参照。

## 注意

- 実施結果は、ブラウザの localStorage に保存される。キーは `uds-screen-test:v1:` にファイルのパスを付けたもの。そのため、ファイルの置き場所を変えると、保存した結果は引き継がれない。結果を残したいときは、先に JSON か CSV に書き出しておく。
- 外部の検証会社向けに書き直す件（手順の具体化、準備データの具体化、「要確認」の確定）は、MTG で方針を決めるまで保留中（2026-11-02 時点）。
