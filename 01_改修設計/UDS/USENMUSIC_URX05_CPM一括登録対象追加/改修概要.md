# 改修概要 — USEN MUSIC（URX-05）のCPM一括登録対象追加

**作成日:** 2026-07-01
**対象システム:** UDS（import_contract Lambda）
**依頼元:** 和田さん（[Google Chat](https://chat.google.com/room/AAQAx6IcDLQ/8PZnvZDI9vw/8PZnvZDI9vw?cls=10)）

---

## 1. 改修目的

`import_contract` のCPM案件一括登録対象サービスコード（`SERVICE_CDS_CPM_MUSIC_SETTING`）に、新規追加されるUSEN MUSIC（URX-05）の4サービスコードを追加し、これらの契約についても契約データ取り込み時にBGM関連レコード（`contract_bgms`／`contract_bgm_sound_images`／`contract_bgm_genres`）が自動生成されるようにする。

## 2. 追加対象サービスコード

| サービスCD | サービス名 |
|---|---|
| U80 | USEN MUSIC スタンダードPLAN（URX-05） |
| U81 | USEN MUSIC リプレイスPLAN（URX-05） |
| U82 | USEN MUSIC ライトPLAN（URX-05） |
| U83 | USEN MUSIC エントリーPLAN（URX-05） |

## 3. 変更内容

`各サービスリポジトリ/uds/import_contract/index.js:137`

```js
// 変更前
const SERVICE_CDS_CPM_MUSIC_SETTING = ['U01', 'U10', 'U14', 'U15', 'U16', 'U69', 'U70', 'G05', 'G06'];

// 変更後
const SERVICE_CDS_CPM_MUSIC_SETTING = ['U01', 'U10', 'U14', 'U15', 'U16', 'U69', 'U70', 'G05', 'G06', 'U80', 'U81', 'U82', 'U83'];
```

この配列は以下2箇所で参照される（コード変更なし、対象サービスコードが増えるのみ）。

- 新規契約（INSERT）時: `index.js:1056`
- 既存契約（UPDATE）時: `index.js:1087`

## 4. 影響範囲

| ファイル | 種別 | 内容 |
|---|---|---|
| `import_contract/index.js` | 改修 | `SERVICE_CDS_CPM_MUSIC_SETTING` に4コード追加（1行のみ） |

ロジック自体（`import_bgm.save` 等）は変更しない。

## 5. スコープ外・確認事項

- `device_types` マスタへの U80〜U83（`neos_item_cd → service_cd`）データ投入は本改修のスコープ外。投入されていないとサービスコードが解決できず、CPM一括登録が動作しない
- 対象契約の `unis_industry_cd`（TSV25列目）に対応するレコードが `industries` マスタに存在しない場合、`import_bgm.save` 内の `select_industry` が空を返し、後続処理でエラーとなる。マスタ整備状況の確認が必要
- [ ] `device_types` マスタ投入のタイミングをデータ担当者と調整する

## 6. テスト観点

| パターン | 確認内容 |
|---|---|
| U80〜U83いずれかの新規契約データ投入 | `contract_bgms`／`contract_bgm_sound_images`／`contract_bgm_genres`（9件）が自動生成されること |
| U80〜U83いずれかの既存契約データ更新 | 同上（UPDATE経路） |
| `umusic_sequential_cd` が既に設定済みの契約 | 自動生成がスキップされること（既存仕様通り） |
| `contract_status_cd` が解約(3)／キャンセル(4)の契約 | 自動生成が行われないこと |
| 同一 `contract_cd` での再実行 | 二重登録されず処理がスキップされること（`exist_bgms` 判定） |
| 既存対象コード（U01等）の契約データ | 従来通り動作すること（リグレッション） |
