# UDS クエリ負荷改修概要

インシデント報告書: `UDS_incident_report_20260624.md`

---

## 背景

2026年6月24日、UDS 本番Aurora MySQL にてDB接続数が上限（max_connections: 135）に到達し、UDSログインで500エラーが発生した。原因は複数の画面で「ページを開いた際にデフォルトで重いSQLが実行される」設計であり、ユーザーの連打・同時アクセスによって並列実行が積み上がったことによる。

---

## 改修方針

- **検索ボタン押下後のみSQLを発行する**（画面を開いただけでは実行しない）
- UIの連打防止ではなく、SQLそのものを発行しない設計変更
- 検索フォームのない画面（端末回収状況登録・マスター管理端末一覧）には「一覧を表示」ボタンを追加する
- 端末回収状況登録のみ、ソートリンクを含む一覧表示トリガーに**オーバーレイ（連打防止）**を追加する
- 未検索時は「**検索条件を入力して「検索」ボタンを押してください。**」、検索結果0件時は「**項目がありません。**」と表示を出し分ける（検索フォームのない画面は初期表示時に何も表示しない）

---

## 改善対象

| クエリ | 発生元 | 改修方式 |
|--------|--------|----------|
| ① serials カウント | 端末回収状況登録画面 | ボタン追加方式（後述 B） |
| ② shipping_requests カウント | 引き当て画面ほか | Presenter_Pagination 共通修正（後述 A） |

## 変更方針

### A. 検索フォームあり画面（5画面）── `Presenter_Pagination` 共通修正

以下の画面は全て `Presenter_Pagination` を継承しており、**1ファイルの修正で一括対応できる**。

| 画面 | URL |
|------|-----|
| 引き当て | `/manage/center/request` |
| キッティング | `/manage/center/kitting` |
| 出荷 | `/manage/center/shipment` |
| 紛失報告リスト | `/manage/center/device/lost` |
| 発送状況確認（現地） | `/manage/center/shipping/request` |

**修正内容**: `Presenter_Pagination::view()` に「検索パラメータがない初期表示はSQLを実行しない」ガードを追加する。

```php
public function view() {
    parent::view();

    if (!$this->is_searched()) {
        // 検索未実行 → SQLを叩かずに空の状態を返す
        $this->_view->set_safe('pager', null);
        $this->_view->set_safe('data_count', 0);
        $this->_view->set_safe('show_list', false);
        $this->rows = [];
        return;
    }

    $data = $this->get_search_data();
    // ... 既存の get_count() / get_rows() 処理
}

// is_searched(): GETパラメータに検索条件が1つでも含まれるか判定
```

各 presenter には既に `$search_detail_keys` や `$sort_keys` が定義されているため、
これらを活用して「何らかの検索条件が送信されているか」を判定する。

### B. 検索フォームなし画面（端末回収状況登録・マスター管理端末一覧）── ボタン追加

以下の画面は検索フォームを持たないため、**「一覧を表示」ボタンを追加**し、ボタン押下後のみ SQL が実行される設計に変更する。

| 画面 | URL | ルート |
|------|-----|--------|
| 端末回収状況登録 | `/manage/branch/device/return` 等 | branch・cp・hoshu |
| マスター管理・端末一覧 | `/manage/master/device` | master |

各画面の対応内容:

| 対応 | 端末回収状況登録 | マスター管理・端末一覧 |
|------|:--------------:|:--------------------:|
| presenter `?show` ガード追加 | ✅ | －（実装済み） |
| view「一覧を表示」ボタン追加 | ✅ | ✅ |
| ソート非対応ヘッダを `<a>` → `<span>` | ✅ | － |
| `history.replaceState`（F5リロード対応） | ✅ | ✅ |
| 連打防止オーバーレイ | ✅ | ✅ |

#### B-1. presenter の修正（`?show` ガード）

**端末回収状況登録のみ**（マスター管理・端末一覧は実装済み）。  
`presenter/branch/device/return/index.php` の `view()` 先頭に追加:

```php
public function view() {
    if (!Input::get('show')) {
        // 初期表示 or リロード → SQLを走らせない
        $this->_view->set_safe('pager', null);
        $this->_view->set_safe('data_count', 0);
        $this->_view->set_safe('show_list', false);
        $this->rows = [];
        $this->late_row_count = 0;
        return;
    }

    parent::view();  // get_count() + get_rows() を実行

    // 30日超過件数カウント（既存処理）
    $query = DB::select(...);
    $this->late_row_count = $result[0]['count'];
}
```

#### B-2. view の修正（「一覧を表示」ボタン追加）

**両画面共通**。各画面の適切な箇所に追加:

```html
<form action="[現在のURL]" method="get">
    <div class="c-form-action">
        <button type="submit" name="show" value="1"
                class="c-btn is-search c-font-size is-small js-show-list-btn">
            一覧を表示
        </button>
    </div>
</form>
```

端末回収状況登録では、ソートリンクが `?show=1` を引き継ぐため、ソート後も一覧は表示されたまま（`Common_Util::get_modifyed_query_string` がGETパラメータを引き継ぐ）。

#### B-3. リロード時に初期状態へ戻る（`history.replaceState`）

**端末回収状況登録のみ**（マスター管理・端末一覧は動作確認の上判断）。  
`?show=1` のURLでページ表示後、JavaScriptでパラメータを除去し、F5リロードで一覧が消える設計にする。

`script.js` に追加:

```javascript
if (window.location.search.includes('show=1')) {
    history.replaceState({}, document.title, window.location.pathname);
}
```

#### B-4. 連打防止オーバーレイ（「一覧を表示」ボタン専用）

**端末回収状況登録のみ**。ボタンクリック時にオーバーレイを表示し、ページ遷移完了まで次のクリックを受け付けない。

`script.js` に追加:

```javascript
$(document).on('click', '.js-show-list-btn', function () {
    if ($('#js-loading-overlay').length) {
        return false;
    }
    $('body').append(
        '<div id="js-loading-overlay" style="' +
            'position:fixed;top:0;left:0;width:100%;height:100%;' +
            'z-index:9999;background:rgba(0,0,0,0.3);cursor:wait;' +
        '"></div>'
    );
});
```

### C. 未検索時メッセージの改善（全対象画面共通）

現状は未検索時と検索結果0件時の両方で「項目がありません。」が表示され、ユーザーに操作方法が伝わらない。`show_list` フラグを介してPresenterとViewの責務を分離し、画面ごとに適切な表示を実現する。

**設計方針**:
- Presenterの役割: 「一覧を表示するか否か」を `show_list = false` で伝えるだけ
- Viewの役割: `show_list` が `false` のとき、何を表示するかを各view側で決める

#### C-1. 共通パーシャル新規作成（`parts/nosearch.php`）

検索フォームあり画面（A）の初期表示専用メッセージ:

```html
<div class="c-data">
    <div class="c-data__notfound">
        <p class="c-data__notfound--text c-font-size is-small is-noweight">
        検索条件を入力して「検索」ボタンを押してください。
        </p>
    </div>
</div>
```

#### C-2. presenter のガードに `show_list = false` を追加

各 presenter のガードブロック（A・B ともに）に1行追加する:

```php
$this->_view->set_safe('show_list', false);
```

追加対象 presenter ファイル:

| ファイル | 対象画面 |
|---------|---------|
| `presenter/pagination.php` | キッティング・出荷（常時URLパラメータなし画面） |
| `presenter/center/device/lost/index.php` | 紛失報告リスト |
| `presenter/center/request/index.php` | 引き当て |
| `presenter/branch/shipping/request/index.php` | 発送状況確認 |
| `presenter/branch/device/return/index.php` | 端末回収状況登録（`?show` ガード内） |
| `presenter/master/device/index.php` | マスター管理・端末一覧（`?show` ガード内） |

#### C-3. 対象画面ビューの条件分岐変更

**検索フォームあり画面（A）のview** — `else` に `nosearch` を書く:

```php
<?php if ($show_list ?? true): ?>
    <?php if ($data_count > 0): ?>
        <!-- テーブル -->
    <?php else: ?>
        <?php echo View::forge('parts/nodata'); ?>
    <?php endif; ?>
<?php else: ?>
    <?php echo View::forge('parts/nosearch'); ?>
<?php endif; ?>
```

**検索フォームなし画面（B・D）のview** — `else` を書かない（何も表示しない）:

```php
<?php if ($show_list ?? true): ?>
    <?php if ($data_count > 0): ?>
        <!-- テーブル -->
    <?php else: ?>
        <?php echo View::forge('parts/nodata'); ?>
    <?php endif; ?>
<?php endif; ?>
```

> `$show_list ?? true` というデフォルト値により、**改修対象外の画面には影響しない**（`show_list` が未定義のまま → `true` として動作し、既存の挙動が維持される）。

### D. 非検索画面（マスター管理・端末一覧）── ボタン追加

`/manage/master/device`（マスター管理 > 端末一覧）は検索フォームを持たない一覧画面だが、`Presenter_Pagination` を継承しているため、Aの共通ガードが適用されると **初期表示で一覧が消える**。

presenter 側のガード（`?show` チェック）は実装済みのため、**view にボタンを追加するだけ**で対応できる。

```html
<button type="submit" name="show" value="1" class="c-btn is-search ...">
    一覧を表示
</button>
```

端末回収状況登録（B）と異なり以下の対応は不要:
- ソートリンクの `<a>` → `<span>` 変更（ソート設計が異なるため）
- `history.replaceState`（ソートリンクが `?show=1` を引き継ぐかどうかを確認の上判断）
- オーバーレイ（連打防止）

> **メッセージ表示**: 検索フォームがないため、初期表示時に「検索条件を入力して...」のメッセージは表示しない。C-3のviewパターンは「検索フォームなし画面」側を適用する。
