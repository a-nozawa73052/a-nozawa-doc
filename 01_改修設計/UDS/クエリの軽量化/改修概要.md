# UDS クエリ負荷改修概要

インシデント報告書: `UDS_incident_report_20260624.md`

---

## 背景

2026年6月24日、UDS 本番Aurora MySQL にてDB接続数が上限（max_connections: 135）に到達し、UDSログインで500エラーが発生した。原因は複数の画面で「ページを開いた際にデフォルトで重いSQLが実行される」設計であり、ユーザーの連打・同時アクセスによって並列実行が積み上がったことによる。

---

## 改修方針

- **検索ボタン押下後のみSQLを発行する**（画面を開いただけでは実行しない）
- UIの連打防止ではなく、SQLそのものを発行しない設計変更
- 端末回収状況登録のみ、新設する「一覧を表示」ボタンとソートリンクに**オーバーレイ（連打防止）**を追加する

---

## 改善対象

| クエリ | 発生元 | 改修方式 |
|--------|--------|----------|
| ① serials カウント | 端末回収状況登録画面 | ボタン追加方式（後述 B） |
| ② shipping_requests カウント | 引き当て画面ほか | Presenter_Pagination 共通修正（後述 A） |

---

## 変更方針

### A. 検索フォームあり画面（5画面）── `Presenter_Pagination` 共通修正

以下の画面は全て `Presenter_Pagination` を継承しており、**1ファイルの修正で一括対応できる**。

| 画面 | URL |
|------|-----|
| 引き当て | `/manage/center/request` |
| キッティング | `/manage/center/kitting` |
| 出荷 | `/manage/center/shipment` |
| 紛失報告リスト | `/manage/center/device/lost` |
| 発送状況確認（現地） | `/manage/center/shipping/request` |

**修正内容**: `Presenter_Pagination::view()` に「検索パラメータがない初期表示はSQLを実行しない」ガードを追加する。

```php
public function view() {
    parent::view();

    if (!$this->is_searched()) {
        // 検索未実行 → SQLを叩かずに空の状態を返す
        $this->_view->set_safe('pager', null);
        $this->_view->set_safe('data_count', 0);
        $this->rows = [];
        return;
    }

    $data = $this->get_search_data();
    // ... 既存の get_count() / get_rows() 処理
}

// is_searched(): GETパラメータに検索条件が1つでも含まれるか判定
```

各 presenter には既に `$search_detail_keys` や `$sort_keys` が定義されているため、
これらを活用して「何らかの検索条件が送信されているか」を判定する。

### B. 検索フォームなし画面（端末回収状況登録）── ボタン追加

端末回収状況登録画面は検索フォームがないため、**「一覧を表示」ボタンを新たに追加**し、
ボタン押下後のみ SQL が実行される設計に変更する。

この画面には以下の3つの仕様を追加する。

#### B-1. presenter の修正（`?show` ガード）

`presenter/branch/device/return/index.php` の `view()` 先頭に追加:

```php
public function view() {
    if (!Input::get('show')) {
        // 初期表示 or リロード → SQLを走らせない
        $this->_view->set_safe('pager', null);
        $this->_view->set_safe('data_count', 0);
        $this->rows = [];
        $this->late_row_count = 0;
        return;
    }

    parent::view();  // get_count() + get_rows() を実行

    // 30日超過件数カウント（既存処理）
    $query = DB::select(...);
    $this->late_row_count = $result[0]['count'];
}
```

#### B-2. view の修正（「一覧を表示」ボタン追加）

バーコードスキャンエリアと「回収依頼一覧」の間に検索フォームを追加:

```html
<form action="[現在のURL]" method="get">
    <div class="c-form-action">
        <button type="submit" name="show" value="1"
                class="c-btn is-search c-font-size is-small js-show-list-btn">
            一覧を表示
        </button>
    </div>
</form>
```

ソートリンクは `?show=1` を引き継いだ形で生成されるため、
ソート操作後も一覧は表示されたままになる（既存の `Common_Util::get_modifyed_query_string` がGETパラメータを引き継ぐ）。

#### B-3. リロード時に初期状態へ戻る（`history.replaceState`）

`?show=1` を含む URL でページが表示されたとき、JavaScript で URL からパラメータを除去する。
これにより F5 リロード時はパラメータのないURLが再読み込みされ、一覧は表示されない。

`script.js` に追加:

```javascript
// 端末回収状況登録：一覧表示後にURLを初期化（F5リロードで一覧が消える）
if (window.location.search.includes('show=1')) {
    history.replaceState({}, document.title, window.location.pathname);
}
```

#### B-4. 連打防止オーバーレイ（「一覧を表示」ボタン専用）

「一覧を表示」ボタン（`.js-show-list-btn`）クリック時にオーバーレイを表示し、
ページ遷移完了まで次のクリックを受け付けない。ページ遷移後はDOMリセットによりオーバーレイは自然消滅する。

`script.js` に追加:

```javascript
$(document).on('click', '.js-show-list-btn', function () {
    if ($('#js-loading-overlay').length) {
        return false;
    }
    $('body').append(
        '<div id="js-loading-overlay" style="' +
            'position:fixed;top:0;left:0;width:100%;height:100%;' +
            'z-index:9999;background:rgba(255,255,255,0.5);cursor:wait;' +
        '"></div>'
    );
});
```

## 変更ファイル一覧

### A. Presenter_Pagination 共通修正（5画面）

|----------|----------|----------|

### B. 端末回収状況登録

| ファイル | 変更内容 | 影響ルート |
|----------|----------|------------|
| `presenter/branch/device/return/index.php` | `?show` ガード追加（B-1） | branch・cp（継承）・hoshu（presenter 流用） |
| `views/branch/device/return/index.php` | ボタン追加（B-2）・ソート非対応ヘッダを `<a>` → `<span>` に変更 | branch・hoshu（view 流用） |
| `views/cp/device/return/index.php` | ボタン追加（B-2）・ソート非対応ヘッダを `<a>` → `<span>` に変更 | cp（独自 view のため別途） |
| `public/assets/js/script.js` | `history.replaceState`（B-3）・オーバーレイ（B-4）追加 | branch・cp・hoshu 共通 |

> **center は対象外**: `/manage/center/device/return` は `Presenter_Base` を継承しており、一覧表示の処理自体が存在しない。

## インデックス追加との関係

| 対策 | 端末回収状況登録 | 引き当て等5画面 |
|------|----------------|----------------|
| 今回の設計変更 | ✅ ボタン追加で対応 | ✅ Presenter 修正で対応 |
| インデックス追加 | **引き続き推奨**（ボタン押下時のクエリを高速化） | 発火頻度が激減するため優先度は低下 |

端末回収状況登録は「ボタン押下時のクエリ」が残るため、
インデックス追加（`add_indexes.sql` のクエリ①）も引き続き実施することを推奨する。
