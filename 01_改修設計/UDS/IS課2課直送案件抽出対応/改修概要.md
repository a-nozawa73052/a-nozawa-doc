# UDS 直送案件検索画面 改修概要（IS課2課の案件抽出対応）

**作成日:** 2026-09-02

---

## 1. 背景・経緯

今期よりIS課が1課・2課に分かれ、両課で直送を獲得している。

依頼元（亀山さん）からの連絡内容：

> 今期からIS課が1課と2課でわかれているですが、両課で直送獲得しております。
> UDSでIS課案件を絞ると1課分しか抽出できず、2課分が抽出できない状態です。
> 営業所属部署名の箇所です。（UDS連携自体はされております）
> こちらをIS課で絞った際に両課の案件が抽出できるよう設定をお願いしたいです。

UDS「直送案件」検索画面（`/manage/jimu/shipment/list`）の「営業所属部署名」で「IS課」にチェックを入れて検索すると、内部的には `contracts.sales_branch_cd` を特定コードでIN検索している。現状このコード一覧に2課の部署コード（`2105010000`）が含まれていないため、2課分の契約が検索結果から漏れている。UNIS/NEOS側からUDSへの部署コード連携自体は正しく行われている（＝`contracts.sales_branch_cd`には`2105010000`が入ってくる）ことは確認済みで、UDS側の検索条件定義の不足が原因。

---

## 2. 改修方針

「IS課」で絞り込んだ際に1課・2課の両方の契約が抽出されるよう、`config/define.php` の `is_branch_cd`（「IS課」チェック時に検索条件のIN句へ展開される部署コード一覧）に2課の部署コード `2105010000` を追加する。

- 画面上のプルダウン（チェックボックス）の選択肢自体（「IS課」「アライアンス課」の2項目）は変更しない
- 「IS課1課／IS課2課」を画面上で個別に絞り込みたいという要件ではなく、既存の「IS課」フィルタが両課の案件を拾うようにする、という要件のため、UI・プレゼンター・モデルのロジック自体に変更は不要で、定数配列への値追加のみで対応する

---

## 3. 変更内容

### `fuel/app/config/define.php`（909-913行付近）

```php
// 変更前
'is_branch_cd' => array(
    '1' => '2105000000',
    '2' => '2108000200',
),

// 変更後
'is_branch_cd' => array(
    '1' => '2105000000',
    '2' => '2108000200',
    '3' => '2105010000',
),
```

配列のキー（`'1'`, `'2'`, `'3'`）は連番の識別子であり業務上の意味は持たず、プレゼンター（`presenter/jimu/shipment/list/index.php`）が`foreach`ではなく`array_merge`でこの配列全体を検索条件へ展開するだけのため、キーの追加位置・番号に制約はない。

## 5. 実装箇所（参考・変更なし）

以下は今回変更しないが、`is_branch_cd` を参照している既存ロジック。

- `modules/manage/classes/presenter/jimu/shipment/list/index.php`（262-277行）: `sb`パラメータから`is_branch_cd`/`alliance_branch_cd`を検索条件配列に変換
- `classes/model/direct/shipment.php`（328-331行）: `contracts.sales_branch_cd` を `IN` 検索するクエリ組み立て

---

## 6. 影響範囲

事前にコード全体を横断調査し、以下を確認済み。

- `is_branch_cd` / `alliance_branch_cd` / `sales_branch_cd`（config）、および `contracts.sales_branch_cd` / `sales_branch_name`（カラム）を参照しているのは、直送案件検索画面の検索条件組み立てとCSV/画面への値表示のみで、権限制御・通知振り分け・集計バッチ・金額計算・担当者自動割当等の業務ロジック分岐は存在しない
- 一覧表示と検索結果の総件数（ページネーション件数）は同じクエリ（`model/direct/shipment.php`の`search()`）を共有しているため、本改修により総件数も2課分を含めた正しい件数になる
- 直送全項目CSV等の出力は検索結果に含まれるデータをそのまま出力する構造のため、本改修により2課分の契約もCSV出力対象に含まれるようになる（新たな不具合ではなく、検索条件修正に伴う想定通りの効果）
- 「アライアンス課」の検索条件（`alliance_branch_cd`）には手を加えないため、影響なし

## 9. デプロイ・ブランチ運用

- UDSのデプロイは環境ごとに手動`git pull`（本番=`main`、ステージング=`staging`、開発=`develop`）で反映する運用のため、対応時点で`develop`には長期未リリースの変更が多数滞留していた
- 本改修は影響範囲が限定的な軽微な修正のため、`main`ベースの`hotfix/is-branch-cd-add-entry`ブランチで対応し、`develop`の未リリース分を巻き込まずに先行反映する
- `main`へのマージ後、`staging`・`develop`にも同じ変更をcherry-pickし、ブランチ間の差分を解消する
