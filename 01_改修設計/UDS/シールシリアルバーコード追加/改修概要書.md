- センターのキッティング画面から出力する「宛先シール」（顧客CD・出荷先・設置先名・型番・S/Nを印字）に、シリアルのバーコードを追加したいという要望
- 先行して実施した「UDSシール並び替え修正」と同じ時期に確認を依頼されていた件

### 依頼内容（チャット原文の要約）

| # | 要望 |
|---|------|
| 1 | シールにシリアルのバーコードを追加したい（写真の見本では、S/N欄の下に2品目分のバーコードを横並びで配置） |
| 2 | 行が増えるため、上下の余白をなるべくなくし、文字サイズを揃えたい。枠の幅をフル活用して文字を大きくしたい（シールサイズが小さい対象があり、字が小さくて見にくい） |
| 3 | 特定のセット名に対して、バーコードの有無を設定したい |

### 課題

| 課題 | 内容 |
|-----|------|
| バーコードの種類 | 見本はCode39形式だが、シリアルに小文字（`zy32dj64lx` 等）や記号（`DS-ASTB1A-U(UDS)`、`GT133_PPT_0010` 等）を含むものがあり、標準のCode39では表現できない |
| バーコードの幅 | シールの幅は約60mm。2つを横並びにすると1つあたり約25〜28mmしか取れず、11桁程度でも読み取りがぎりぎりになる（詳細は「4. 期待効果・定量見積」） |
| 文字サイズ | 現在は全項目6pt固定で、見にくい |
| 有無の設定先 | セットマスタ（`sets`）には `set_cd` / `set_name` / `center_cd` しかなく、バーコードの有無を判定する項目がない |

### 目的

- 出荷・検品作業で、シリアルをスキャナで読み取れるようにする（用途はQAで確認中）
- シールの文字を大きくし、視認性を上げる

## 2. 現行仕様

### 出力箇所

| 項目 | 内容 |
|-----|------|
| 画面 | センター キッティング画面（シール出力ボタン） |
| Controller | `fuel/app/modules/manage/classes/controller/center/kitting.php` の `action_download_shipment_label_save()` |
| PDF生成クラス | `fuel/app/classes/pdf/creater/shipment/label.php`（`Pdf_Creater_Shipment_Label`、TCPDF/FPDI） |
| 背景テンプレート | `assets/pdf/shipment.pdf`（罫線を背景PDFで持ち、その上に文字を座標指定で書き込む方式） |
| 出力データ | 対象依頼と同じセットの全依頼（`get_set_shipping_request()`） |

### レイアウト

- 1枚に2品目（型番1・S/N1／型番2・S/N2）。3品目以上のときは複数枚に分かれる（1/2、2/2 …）
- フォントは全項目6pt固定
- 文字数の上限: 顧客CD 13文字、出荷先 16文字、設置先名 44文字、型番 13文字
- S/Nは13桁を超えると2行に折り返して表示（最大26桁）
- ダミーシリアル（`dummy_serial_id` あり）の品目は「シリアル管理対象外」と印字
- UDS内で1次元バーコードを出力している箇所は現状なし（QRコードシールは `pdf/creater/qrcode/label.php` に別途あり）

### 未決の設計判断（QA回答後に `/design-forward` で整理）

| 論点 | 選択肢 |
|-----|-------|
| バーコードの種類 | Code128（推奨。小文字・記号に対応し、幅も短い）／Code39 |
| バーコードの配置 | A: 1行に1つ、全幅で配置／B: 1枚1品目／C: 2つ横並び（長い桁の型番は対象外） |
| 有無の判定単位 | セット単位／型番（品目）単位 |
| 有無の設定方法 | 設定ファイル（改修小）／DBフラグ＋画面（改修大、DB変更あり） |

## 4. 期待効果・定量見積

### シリアル桁数の分布（`serials.serial_cd`、2026-10-13時点、966,730件）

| 桁数 | 件数 | 備考 |
|-----|-----|------|
| 1〜7 | 609 | テストデータを含む（`s`、`testserial` 等） |
| 8〜13 | 701,273 | 大半がこの範囲 |
| 14〜16 | 10,973 | URX、UAC-05、DS-ASTB1A 等 |
| 17〜18 | 47,104 | UAC-01W/02W/02P系と思われる（要確認） |
| 19 | 206,750 | 大半が `NOSERIAL0000…` 形式のダミー値 |
| 24〜25 | 21 | UAC-01W、UT8-4TL、UT6-G10。異常値の可能性 |

- カラム定義は `varchar(50)`
- 19桁のダミー値は、現行どおり「シリアル管理対象外」としてバーコードを出さない想定。ただし判定に使う `dummy_serial_id` と `NOSERIAL` 形式が一致しているかは要確認

### Code128のバーコード幅の目安（前後の余白込み）

幅(mm) = (11 × 桁数 + 55) × 細いバー1本の幅

| 桁数 | 0.25mm（203dpiで2ドット、安定して読める） | 0.19mm | 0.125mm（203dpiで1ドット、読み取りは厳しい） |
|-----|------|------|------|
| 11 | 約44mm | 約34mm | 約22mm |
| 13 | 約50mm | 約38mm | 約25mm |
| 16 | 約58mm | 約44mm | 約29mm |
| 17 | 約61mm | 約46mm | 約30mm |
| 25 | 約83mm | 約63mm | 約41mm |

→ シールの幅が約60mmの場合、全幅で配置しても16桁程度までが現実的。2つを横並び（約25〜28mm）にすると、安定して読み取れる桁数はかなり限られる。シールのサイズとプリンタの解像度はQAで確認中。

## 5. 影響範囲・リスク

- 他システムへの影響: なし（UDS内のPDF出力のみ）。設定方法でDBフラグ案を選ぶ場合のみ、UDSのDB変更が発生する
- 他拠点への影響: シールを出力しているのはセンターのキッティング画面のみ。利用拠点はQAで確認中
- リスク:
  - バーコードの読み取り可否はプリンタ・スキャナとの相性に依存する。本番反映前に、テスト環境で印刷したシールを現場のスキャナで読み取るテストが必須
  - レイアウトの変更により、既存の運用（シールの貼付位置や目視確認）に影響が出る可能性がある
  - 背景テンプレートPDFを差し替える場合、旧テンプレートとの切り替えタイミングに注意
