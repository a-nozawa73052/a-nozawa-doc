# 改修概要 — 引き当て・キッティング検品画面の商材（シリアル）表示順序統一

**作成日:** 2026-07-08
**対象ロール:** center（センター）のみ
**対象範囲:** branch / cp / hoshu / external ロールは対象外（権限確認中のため、確定後に別途改修概要を追加）

---

## 1. 背景・経緯

セット品（1依頼に複数の商材が紐づくケース）の件数が多い場合、以下の作業においてシリアルの表示順が型番ごとにまとまっておらず、かつ順序に規則性もないという問題があった。

- 端末引き当て時（引き当て画面）
- キッティング時（キッティング検品画面）
- 宛先シールを貼る際（宛名シール印刷PDF）

このため作業者が「次に処理すべき端末はどれか」を画面・シール上で判別しづらく、作業効率が低下していた。この課題を解消するため、表示・印字順を型番でグルーピングし、規則性を持たせる本対応を行う。

---

## 2. 改修目的

以下3箇所で表示・出力される商材（シリアル）の並び順を、下記ルールに統一する。

> **型番でグルーピングした上で、依頼生成日時（新しい順）で表示する**

| # | 対応内容 |
|---|---------|
| ① | 引き当て画面のシリアル並び順を変更する |
| ② | キッティング検品画面のシリアル並び順を①と同様に変更する |
| ③ | 宛名シール印刷PDFの並び順を①②と同様に統一する |

---

## 3. 用語定義

| 用語 | 定義 |
|------|------|
| セット品 | 同一 `unis_customer_cd` + `request_date` + `neos_item_pac_cd`（型番グループ`set_cd`）を持つ `shipping_requests` の集合（`Common_Shipping_Request::get_set_common_part_query()` で取得） |
| 依頼生成日時 | `shipping_requests.created_at`（DBレコード作成日時） |
| 型番 | `shipping_requests.model_number` |

---

## 4. 改修方針

型番でグルーピングした上で依頼生成日時の新しい順に並べるため、以下のソート条件を追加する。

```sql
ORDER BY shipping_requests.model_number ASC, shipping_requests.created_at DESC
```

- 型番（コード順）でグルーピングし、同一型番の商材がまとまって表示されるようにする（**方針A**として確定）。
- グループ内は依頼生成日時が新しい順になるようにする。

---

## 5. 対応① — 引き当て画面のシリアル並び順

### 5-1. 対象画面

`/manage/center/assign/serial/{id}`

### 5-2. 変更仕様

| 項目 | 変更前 | 変更後 |
|------|-------|-------|
| ソート条件 | `created_at` 降順のみ | `model_number` 昇順 → `created_at` 降順 |
| 型番のグルーピング | なし（同一型番でも離れて表示される場合がある） | あり（同一型番がまとまって表示される） |

### 5-3. 実装箇所

#### `各サービスリポジトリ/uds/uds-web/src/public_html/fuel/app/modules/manage/classes/controller/center/assign.php`（1062-1087行, `get_set_shipping_request()`）

```php
// 変更前
$query->order_by('shipping_requests.created_at', 'desc');

// 変更後
$query->order_by('shipping_requests.model_number', 'asc');
$query->order_by('shipping_requests.created_at', 'desc');
```

## 6. 対応② — キッティング検品画面のシリアル並び順

### 6-1. 対象画面

`/manage/center/kitting/view/{id}`

### 6-2. 変更仕様

| 項目 | 変更前 | 変更後 |
|------|-------|-------|
| ソート条件 | 指定なし（`order_by` 未設定、DB既定順） | `model_number` 昇順 → `created_at` 降順 |
| 型番のグルーピング | なし | あり |

### 6-3. 実装箇所

#### `各サービスリポジトリ/uds/uds-web/src/public_html/fuel/app/modules/manage/classes/controller/center/kitting.php`（1162-1182行, `get_set_shipping_request()`）

```php
// 変更前
$rows = $query->execute()->as_array();
return $rows;

// 変更後
$query->order_by('shipping_requests.model_number', 'asc');
$query->order_by('shipping_requests.created_at', 'desc');
$rows = $query->execute()->as_array();
return $rows;
```

## 7. 対応③ — 宛名シール印刷PDFの並び順

### 7-1. 対象機能

キッティング検品画面「宛先シール印刷」ボタン（`action_download_shipment_label_save`）

### 7-2. 変更仕様

| 項目 | 変更前 | 変更後 |
|------|-------|-------|
| PDF印字順 | ②のデータ取得順（不定） | ②のソート後の順（型番グルーピング＋依頼生成日時降順） |
| PDF生成ロジック（`foreach`でそのまま印字） | 変更なし | 変更なし |

### 7-3. 実装箇所

- `各サービスリポジトリ/uds/uds-web/src/public_html/fuel/app/modules/manage/classes/controller/center/kitting.php`（968-1001行, `action_download_shipment_label_save()`）
  - `get_set_shipping_request()`（②で修正済み）をそのまま呼び出しているため、コード変更は不要。
- `各サービスリポジトリ/uds/uds-web/src/public_html/fuel/app/classes/pdf/creater/shipment/label.php`（27-53行, `create()`）
  - 渡された配列をそのまま `foreach` で印字する実装のため、変更不要。

## 9. スコープ外

- branch / cp / hoshu / external ロールの同等画面（`branch/assign.php` 等）は対象範囲を確認中のため、本改修には含めない。範囲確定後、別途改修概要を追加する。
- 型番グループ自体の並び順は「型番コード昇順」とする（方針A）。「グループ内最新`created_at`の降順でグループ順を決定する」案（方針B）は不採用。

---

## 10. テスト観点

| パターン | 期待する動作 |
|---------|------|
| セット品が複数の型番を含む場合 | 同一型番の商材がまとまって表示される |
| 同一型番内に複数レコードがある場合 | `created_at` が新しいものが先に表示される |
| 引き当て画面・キッティング検品画面 | 同じセット品に対して両画面で同一の並び順になっている |
| 宛名シール印刷PDF | 画面表示順とPDF内の印字順が一致している |
| 単一型番・単一レコードのセット品 | 従来通り1件のみ表示・印字される（回帰確認） |
