# **改修概要：import\_neos\_uairplan 不具合修正（3件）**

# **背景・経緯**

NEOSからの契約情報インポート処理（`import_neos_uairplan`）において、バンドコード不備によるエラー・CAF存在チェックの条件不備・解約撤回時のデータ更新漏れに関する3件の不具合が確認された。

---

# **現行の問題点**

## 【不具合①】バンドコードがnull/空文字の場合にエラーが発生する

連携ファイルのバンドコード（`unis_band_cd`）が null または空文字の契約に `contract_mdm2_devices` のレコードが存在する場合、エラーが発生することが確認された。

バンドコードが null または空文字の場合、`getNeosItems` 関数が `device_types` テーブルから品目情報を取得できず、`neos_item_name` が `undefined` のまま `updateMdm2Status` 関数に渡される。この状態で `contract_mdm2_devices` にレコードが存在すると、`undefined` を mysql2 のクエリパラメータとして使用しようとしてエラーが発生する。エラーによりトランザクションがロールバックされ、該当ファイル内の全行が更新されない。

## 【不具合②】CAF存在チェックの条件不備（空文字を考慮していない）

`checkSOUserAndAddQueue` 関数内（`index.js` 1459行付近）において、v6解約リクエストを生成しないための条件が `if(ngnCommonId == null)` となっている。
`ngnCommonId` が空文字列（`""`）の場合、`== null` は `false` を返すため、v6解約リクエストが誤って生成されてしまう。

## 【不具合③】解約撤回時に回収日がnullにならない

解約撤回（解約（4）→確定（2））時に端末ステータスを20:回収依頼→19:顧客出庫へ変更する処理（`index.js` 643行付近）において、`shipping_requests.complete_cancel_date` はnullに更新されているが、`serials.collect_request_date` はnullに更新されていない。
（Google Chat起票：https://chat.google.com/room/AAAAL0y9e-M/_HBshhvuj7A/0u_wmDq9X1I?cls=10）

---

# **原因**

## 【不具合①】

### バンドコードが null の場合

`getNeosItems` 関数内の `if(unisBandCd === null) return false;` により `false` が返される。`false` はプリミティブ値であるため、呼び出し元での `neosItems['neos_item_cd'] = null` の代入がサイレント失敗する。結果として `neosItems` は `false` のままとなり、`updateMdm2Status` 内で `neosItems['neos_item_cd']`・`neosItems['neos_item_name']` がともに `undefined` となる。

### バンドコードが空文字の場合

`getNeosItems` 関数の null チェックが `=== null` の厳密比較のため空文字をスルーし、空文字でSQLを実行して0件が返る。空配列 `[]` が `neosItems` に代入され、`neos_item_cd` は `null` に設定されるが `neos_item_name` は `undefined` のままとなる。`updateMdm2Status` 内で `neos_item_name` が `undefined` となり同様のエラーが発生する。

## 【不具合②】

`index.js` 1459行（および同様の箇所、1470・1481・1504・1515行）が以下のような条件になっている：

```javascript
if(ngnCommonId == null){
    // v6解約リクエストを生成しない（処理をスキップ）
    return true;
}
```

JavaScriptの `==` 演算子では `null == null` は `true` だが `"" == null` は `false` であるため、空文字列のケースで意図しない処理が実行される。

## 【不具合③】

`index.js` 643〜648行の解約撤回処理が以下のようになっている：

```javascript
if(deviceStatusCd == '20' && oldContractStatusCd == '4' && contractStatusCd == '2') {
    newDeviceStatusCd = '19';
    newDeviceStatusName = '顧客出庫';
    shippingRequestUpdateColumnToNull = 'complete_cancel_date'; // ← 更新される
    // serialUpdateColumnToNull = 'collect_request_date'; ← 設定が抜けている
}
```

`serials.collect_request_date` をnullにする `serialUpdateColumnToNull = 'collect_request_date'` の設定が漏れており、解約撤回後も回収依頼日が残り続ける。

# **改修内容**

## **基本方針**

| 不具合 | 改修方針 |
| :---- | :---- |
| 不具合① | `getNeosItems` 関数のnull/空文字ガードを撤廃し、呼び出し元（`exports.handler`）で `unis_item_cd`・`unis_band_cd` が両方存在する場合のみ `getNeosItems` を呼び出す方式に変更する。`updateMdm2Status` 関数は、`getNeosItems` の結果としてNeOS品目（`neos_item_cd`・`neos_item_name`）が実際に取得できた場合のみ品目情報を更新し、取得できなかった場合（バンドコードが無い、または該当する`device_types`レコードが無い）は契約ステータス（`contract_status_cd`）の更新のみ行う |
| 不具合② | `if(ngnCommonId == null)` を `if(!ngnCommonId)` に変更し、空文字列も含めてチェックする |
| 不具合③ | 解約撤回処理に `serialUpdateColumnToNull = 'collect_request_date'` を追加する |

不具合①について、`contract_mdm2_devices` の更新処理には以下の2パターンがあり、バンドコードなし時の挙動が異なる。

| 該当パターン | 通常時の更新内容 | バンドコードなし時 |
| :---- | :---- | :---- |
| `contract_cd` が主契約として登録されている場合 | `neos_item_cd`・`neos_item_name` を更新 | 更新対象がないためスキップ |
| `option?_contract_cd` としてオプション登録されている場合 | `option?_contract_status_cd`・`option?_neos_item_cd` を更新 | `option?_contract_status_cd` のみ更新し `option?_neos_item_cd` はスキップ |

## **修正ファイル一覧**

### **`index.js`**

**【不具合①-1】`getNeosItems` 関数のnull/空文字ガードを撤廃し、呼び出し元でガードする方式に変更**

* 修正前：`getNeosItems` 関数内で `if(unisItemCd === null) return false;` / `if(unisBandCd === null) return false;`
* 修正後：`getNeosItems` 関数からnullチェックを削除し、`unis_item_cd`・`unis_band_cd` が両方存在する場合のみ呼び出し元（`exports.handler`）から `getNeosItems` を呼び出す。該当レコードが無い場合は `null` を返す

**【不具合①-2】`updateMdm2Status` 関数の更新クエリをNeOS品目の取得可否で分岐**

NeOS品目（`neos_item_cd`・`neos_item_name`）が取得できなかった場合（バンドコードが無い、またはバンドコードはあるが`device_types`に該当レコードが無い場合）、NeOS品目の更新を省いたクエリを使用する。主契約（`contract_cd`）の場合はNeOS品目のみ更新するクエリのためスキップとする。

```javascript
if(target_contract_cd === 'contract_cd'){
    // 主契約の場合、NeOS品目（neos_item_cd/neos_item_name）が取得できた場合のみ更新
    if (contactNeosItemCd && contactNeosItemName) {
        updateQuery = `UPDATE contract_mdm2_devices SET neos_item_cd = ?, neos_item_name = ?, updated_at = NOW() WHERE contract_cd = ? AND deleted_at IS NULL`;
        updateParam = [contactNeosItemCd, contactNeosItemName, contractCd];
    } else {
        console.log('[updateMdm2Status]バンドコードが空または、変更先の契約品目が取得できないためmdm2の主契約の契約品目の更新は行いません。contract_cd:' + contractCd);
        return true;
    }
} else {
    const target_contract_status_cd = target_contract_cd.replace("cd", "status_cd");
    const target_neos_item_cd = target_contract_cd.replace("contract_cd", "neos_item_cd");

    updateQuery = `UPDATE contract_mdm2_devices SET ${target_contract_status_cd} = ?`;
    updateParam = [contractStatusCd];

    // NeOS品目が取得できた場合のみ品目カラムの更新を追加
    if (contactNeosItemCd && contactNeosItemName) {
        updateQuery += `, ${target_neos_item_cd} = ?`;
        updateParam.push(contactNeosItemCd);
    } else {
        console.log('[updateMdm2Status]バンドコードが空または、変更先の契約品目が取得できないためmdm2のオプション契約の契約品目の更新は行いません。contract_cd:' + contractCd);
    }

    updateQuery += `, updated_at = NOW() WHERE ${target_contract_cd} = ? AND deleted_at IS NULL`;
    updateParam.push(contractCd);
}
```

**【不具合②】CAF存在チェック条件の修正（対象箇所：5か所）**

| :---- | :---- |

- 1515行付近：V6+V4固定IP かつ contractStatusCd が解約orキャンセル

**【不具合③】解約撤回時の collect\_request\_date のnull更新を追加**

`index.js` 643〜648行付近の解約→確定の処理に以下を追加する：

```javascript
if(deviceStatusCd == '20' && oldContractStatusCd == '4' && contractStatusCd == '2') {
```

# **影響範囲**

| 不具合 | 影響範囲 |
| :---- | :---- |
| 不具合① | `updateMdm2Status` が触る `contract_mdm2_devices` テーブルの更新のみに影響する。`contracts` テーブルの更新は `create_update_query` によりバンドコードの有無に関わらず実行されるため、本修正によって契約情報の更新が欠落することはない。バンドコードが無い場合はNeOS品目を特定できないため品目の更新はスキップするが、契約ステータスはバンドコードに依存しないためオプション契約として登録されているケースでは引き続き更新される。`updateComDevices`・`updateMdmDevices`・`checkPPPoEUserAndAddQueue`・`checkSOUserAndAddQueue` については、バンドコードが無い場合も従来通りの動作となり、本修正による影響はない |
| 不具合② | v6 SO解約リクエスト生成処理。`ngnCommonId` が空文字の場合に誤ったリクエストが生成されなくなる |
| 不具合③ | 解約撤回処理。撤回後に `serials.collect_request_date` が正しくnullになる |
