# ADR-0018: 契約内容確認書と作業完了報告書は施工完了時に交付し、書類ごとの発行単位を揃える

- 関係者: 話者名が文字起こしに含まれないため要確認（会議は「ACE-UM開発定例」）
- 出典: 文字起こし 00:40:50〜00:42:48、00:45:38〜00:49:31（Geminiメモ: https://docs.google.com/document/d/1U_YsjhMiKeR-R3wOHp-3ylkF-_ga5CUzu_s9y_pGNnc）
- 備考: 文字起こしの該当箇所は誤変換が特に多く、「Accepted」とするかは要確認。Geminiメモにも決定事項の欄はない。

## コンテキスト
- 申込の流れの中で、顧客には次の書類が出る。
  - 申込書: 最終承認の前（顧客の同意前・社内承認前）と、最終承認の後（顧客の同意も社内承認も済んだもの）で、中身は同じだが意味が違う。
  - 契約内容確認書: 顧客に契約内容を確認してもらうための書類。
  - 作業完了報告書（納品書）: 施工・納品の完了を報告する書類。
- 契約内容確認書を出すタイミングについて、会議では「契約確定時に出すのか、施工完了時に出すのか」が論点になった。
- 最終承認の後は、原則として差し戻しができない。

## 決定
- 契約内容確認書は、契約確定時（最終承認時）ではなく、施工・納品が完了したタイミングで、顧客に説明・交付する。施工が完了したら、すぐに顧客が見られる状態にする。
- 最終承認後の申込書は、ACEからUMEMBERSへ連携し、顧客が確認できる状態にする（確定した内容を顧客が確認できるようにするため）。
- 発行単位は、次のとおりとする。
  - 申込書: 1案件につき、顧客の合意と社内承認まで済んだものが1枚。最終承認前に差し戻された場合は、申込書が複数出ることがある。
  - 契約内容確認書: 店舗単位。
  - 作業完了報告書（納品書）: 店舗単位（文字起こしの発言は不明瞭で、要確認）。
- UDSは、施工完了前にUMEMBERSへ連携が必要な書類があるかを意識する必要があり、現時点で必要なのは最終承認後の申込書だけである。

## 理由
- 通信事業法に基づき、契約確定時ではなく、施工・納品が完了したタイミングで、顧客への説明と書類の交付が必要になるため（発言: 「通信新事業者法」。法令名は要確認）。
- 最終承認前の申込書は、顧客の同意も社内承認も終わっていない書類であり、最終承認後の書類とは意味が違うため。

## 影響・トレードオフ
- 施工完了のタイミング（エンジニアが作業完了を記録した時点）が、書類交付のトリガーになる。
- 最終承認後は差し戻せないため、編集は承認前に済ませておく必要がある。
- 申込書は差し戻しのたびに複数出るため、UMEMBERSなどでの表示は、合意と社内承認まで済んだ1つだけを出す扱いが必要になる（発言は「問題なし」と聞こえる。要確認）。

## 検討した代替案
- 契約内容確認書を、契約確定時（最終承認時）に申込書と同時に出す案 → 通信事業法の要件により、施工完了時とする。
