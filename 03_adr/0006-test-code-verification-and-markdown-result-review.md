# ADR-0006: UDSのLambda（インポート系）はテストコードで検証し、結果をMarkdown/CSVに出力して実装者以外がレビューする

- 決定者・関係者: 野澤有沙、森晨滉、佐々木航太（UDS）
- 出典: 文字起こし 00:00:04〜00:02:25、00:38〜00:41（Geminiメモ: https://docs.google.com/document/d/1eszIMbszV7HGQ8vf6uHg3BmmEAUMtDb47MF18_1JAkQ）
- 備考: 稲田さんとの打ち合わせで森さんが方針を共有・相談する予定（ADR-0009も参照）

## コンテキスト
- 11月から開発を始め、12月にステージングへ上げるタイトなスケジュールである。
- これまでは、テストマトリックスを作り、Lambdaを手動（コマンド操作）で1から10まで動かして確認していた。

## 決定
- Lambdaのテストは、手動のコマンド操作による動作確認をやめ、テストコード（アクション経由）で実施する。
- マトリックスを書く代わりに、テストコードの実行結果をAIでMarkdownまたはCSVに出力する。
- 出力した結果は、実装者以外がレビューする。レビュー担当は森晨滉さんまたは稲田さんで、野澤さんはテストコードも結果もレビューしない。
- テスト結果の出力形式は、レビューしやすいよう森さんがテンプレートを作る。開発者ごとに形式がばらつかないようにするため。
- 単体テストだけの場合でも、テスト結果を誰かがレビューできる形で残す。

## 理由
- スケジュールが厳しく、マトリックス作成よりテストコードの方が正確で速いと考えた（野澤）。
- 森さんは、テスト後に何を実施したかを文章として残す必要があると考えた。結果をMarkdown/CSVに出力して残す形で合意した（野澤: 「その結果を AI でマークダウンになり CSV になりで吐き出して」）。

## 影響・トレードオフ
- 森さんにテンプレート作成の作業が発生する。
- テストコードをそのまま読んで問題が分かるなら、それをレビュー対象にしてもよい（佐々木）。ただし、この点は結論としては固めていない（要確認）。

## 補足
- Geminiメモは「ラムダのテストをアクション経由へ刷新」と要約している。文字起こしでは「コマンド」「アクション」の部分が崩れており、手動のコマンド操作をやめる意図と読み取った（要確認）。
- 文字起こしでは「テストコード」が「チェストコード」「テストコート」などと誤変換されていた。
