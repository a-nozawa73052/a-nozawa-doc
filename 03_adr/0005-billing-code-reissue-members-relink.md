# ADR-0005: 請求先コードが新しく発番された場合のUMEMBERS側の紐づけ運用

- 関係者: 田口智之、井上充
- 出典: 文字起こし 00:28:00〜00:32:16
- 備考: 議論のみで、決定には至っていない。文字起こしの「メンバーズ」はUMEMBERSと解釈した（要確認）

## コンテキスト
- ACEは、現行のUNISからUMEMBERSに送っている請求先マスタ（10/11/13系のファイル。番号は要確認）を移行して、「請求先」と「請求先サブ」（支払い方法やサイクルの違い）を作る予定である。
- 移行で請求先コードが変わってしまうのはまずい、という点は田口・井上で認識が一致している。
- ACEでは、顧客の住所変更や事業者の変更があったとき、新しい請求先を別に作るオペレーションを想定している。その場合、請求先コードが新しく発番される。
- 現行のUNISでも、次の2つの扱いが混在している。
  - 住所を変更して請求先コードを統合（マージ）する。
  - 古い請求先を廃止し、新しい請求先を作る。
- 新しい請求先コードが発番された場合、UMEMBERS側で紐づけをし直す必要がある。ただし、紐づけ直しのきっかけとなる業務フローは把握できていない。

## 選択肢
- 案A: 運用で対応する。新しいコードが発番されるたびに、UMEMBERS側で紐づけをし直す。
- 案B: 新旧の請求先コードを対応づける互換の仕組みを作る。ただし、ケースごとに判断が必要な場合があり、一律には紐づけられない可能性がある（井上）。

## 未解決事項・次のアクション
- [ ] 現行の紐づけ直しの依頼がどのような業務フローで発生しているかを確認する。
- [ ] 案A・案Bのどちらにするかを決める。
