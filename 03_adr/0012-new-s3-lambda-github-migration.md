# ADR-0012: ACE用のインポート系S3・Lambdaをすべて新規に作り、GitLabからGitHubへ移行する

- 決定者・関係者: 野澤有沙、佐々木航太（UDS）
- 出典: 文字起こし 00:39:33〜00:41:11、01:12:40〜01:22:16（Geminiメモ: https://docs.google.com/document/d/1n-Av2kjhakuFZvuhaYh-807svACt8pbR069ukM9-Nd4）

## コンテキスト
- UDSのインポート系Lambdaは、ACE移行後はcom、MDM、MDM2、ダイレクトシップメント、U1、UXコントラクトなどが残り、UDSからACEへのデイリーシップメント出力もある。
- ステージングでは、旧Lambdaと新しいACE用Lambdaが併用される期間がある。本番でも、両方が発火するとデータが壊れるため、旧Lambdaを削除できるまで分けておきたい。

## 決定
- インポート系のS3とLambdaは、すべて新しく作り直す（本番・開発の両環境）。
- 生きているインポート系Lambdaは、すべてGitLabからGitHubへ移行する。
- バケット名は、先頭に「ACE」を付ける（例: エース+contract、エース+com.tsv）。パス（フォルダ構成）は現行を踏襲し、フォルダ名はバケットが被らないように佐々木が決める。
- パス・バケットの設計は、佐々木がスプレッドシートにまとめる。開発者（小澤、上田）が構成を理解できるようにするため。
- 現状はトリガーでバケット作成・設定を手作業しているが、デプロイ時の自動化は別途検討する（ADR-0013）。

## 理由
- 新旧の入り口を分けておけば、ACE側の対応後に旧Lambdaを削除するだけで済み、両方が発火する事故を防げる。

## 未解決事項・次のアクション
- [ ] [佐々木] S3のパス設計・バケット名・開発時の構成定義をスプレッドシートにまとめる（来週木曜から不在の可能性があり、今月中に必要）。
- [ ] [佐々木] デプロイ時に作成するロールを権限も含めて整理し、井上に確認する。自動生成できないかも含めて確認する。
- [ ] [グループ] UDSのUI・出力ファイル（出荷の全項目、UNIS確定Excelなど）を修正する。

## 補足
- 佐々木の確認で、パスは現行を踏襲しても問題ない（特別な要件なし）と確認された。
