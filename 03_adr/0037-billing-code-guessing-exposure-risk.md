# ADR-0037: 請求先コードを入力すると権限のない店舗の情報が見えてしまうリスクをどう扱うか

- 関係者: 話者名が文字起こしに含まれないため要確認（会議は「ACE-UM開発定例_20261104」）
- 出典: 文字起こし 00:19:56〜00:24:46（Geminiメモ: https://docs.google.com/document/d/1cY5J7kJj5DL2sq4CKuffvAGRxIg6Aru8ExA3xBEKeDc）
- 備考: 懸念が共有されただけで、結論は出ていない。文字起こしは誤変換が特に多く、会話の流れに自信がない。

## コンテキスト
- 申込を変更すると、PDFの内容も全部変わる。
- 請求先の構造として、事業者（例: 会社単位）の下に請求先があり、その下に請求先サブ（支払い方法やサイクルの違い）がある、という階層が話された。請求書の情報は請求先に紐づく（要確認）。
- 請求先コードがあるため、その上の概念（事業者）の扱いも論点になった。
- 請求先コードを入力すると、自分が権限を持たない店舗の情報が見えてしまうのではないか、という懸念が共有された（発言: 「適当に言った」コードでも見られるのでは）。

## 判断軸
- コードが推測されやすいか。発言では、コードは桁数があり（6桁・10桁など）ランダムであるため推測は難しい、という趣旨の発言があった（要確認）。
- 請求先コードを入力した後に、権限のチェックがかかるかどうか。
- お客様が画面上でコードを見ることがあるかどうか。発言は「お客様が上で見ることない」と聞こえる（要確認）。

## 現時点の方向性
- 懸念として共有された段階で、対応の方針は決まっていない。「これから確認する」という趣旨の発言で終わっていると聞こえるが、要確認。

## 未解決事項・次のアクション
- [ ] 請求先コードの入力で他店舗の情報が見られないことを、コードの形式と権限チェックの両面で確認する。
- [ ] 事業者・請求先・請求先サブの階層と、権限を持たせる単位を整理する。

## 補足
- Geminiメモは、「事業者および請求先の階層構造、さらに請求先コード等を用いて権限のない店舗情報が閲覧できてしまうリスクについての懸念が共有されている」としている。
