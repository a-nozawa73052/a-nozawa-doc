# ADR-0009: UDSのLambdaは言語をJavaScript（Node.js）のままとする

- 決定者・関係者: 野澤有沙、森晨滉、佐々木航太（UDS）
- 出典: 文字起こし 00:02:25〜00:14:34、00:26:37〜00:32:49、00:43〜00:44（Geminiメモ: https://docs.google.com/document/d/1eszIMbszV7HGQ8vf6uHg3BmmEAUMtDb47MF18_1JAkQ）
- 備考: 言語はJavaScriptのままで確定（野澤さん確認済）。書き直しの範囲と、森さんが提案した開発ツールの採否は未決定。稲田さんと開発メンバーで相談のうえ、森さんが決める

## コンテキスト
- 森さんは、テストの作成コスト削減と検証速度の向上のため、次の方針を提示した。
  - Lambdaは確定。言語はTypeScript（型安全性があり、最新の技術に乗れ、参考情報も多い）。
  - 静的解析にESLintとPrettierを使う。
  - インポート系の共通処理をモジュール単位でファイルに分ける（現在は index.js にまとめて書かれている）。
  - 単体テストはJestで行い、AIにテストコードを書かせる。
- 森さんは、行動が大きく変わると考え、コードを1から書き直す前提だった。
- 佐々木さんは、変わるのは一部なので、コピーして修正点だけ直す方がよいと考えた。この場合は、言語を今のNode.js（JavaScript）のままにして、Node.jsのバージョンだけ上げる（佐々木: 「Node.js は一応上げといてもいいかな」。森さんも「上げときます」と応じた）。

## 決定
- UDSのLambdaは、言語を今のJavaScript（Node.js）のままとする。TypeScriptには移行しない（野澤さん確認済）。
- Node.jsのバージョンは上げる。
- 技術的なやり方の意思決定は森さんが行い、野澤さんへの確認は不要（野澤: 「私に確認とか挟まなくていいです」）。

## 理由
- 今回の変更は一部にとどまる見込みで、コピーして修正点だけ直す方が速く、既存の動作も維持しやすい（佐々木）。
- TypeScriptは学習コストが高い（森さん自身も認めている）。
- 野澤さんがJavaScriptのままで進めると判断した。

## 影響・トレードオフ
- 型安全性や、TypeScript向けの最新の参考情報を使えるという、森さんが挙げた利点は得られない。
- 単体テストは、変更点だけを切り出して行う（ADR-0007）。今のコード構成のため、テストしにくい部分は残る。

## 検討した代替案
- TypeScriptで書き直す案（森）→ 採用しない。型安全性などの利点はあるが、学習コストが高く、全部を切り出して単体テストにすると作業が大きくなる（佐々木）。
