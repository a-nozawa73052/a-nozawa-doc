# ADR-0032: ACE連携のデータ項目のうち、UDS側のカラム長が小さい4箇所をUDS側で修正する

- 決定者・関係者: 野澤有沙（UDS）、坪田亜実、井上充、軽部壮真
- 出典: 文字起こし 00:07:22〜00:10:47（Geminiメモ: https://docs.google.com/document/d/1wDq32q6eY9WTSO9mS0OuvyiOZbPKQ4THPSqUSnFqQks）
- 備考: 修正する4箇所がどの項目かは、文字起こしでは特定できない（要確認）。

## コンテキスト
- 坪田から、午前中にチャットでデータ項目の桁数変更と日時型（デートタイム）の変更が共有されていた。野澤の確認では、桁数変更とデートタイムはUDS側で問題なし。
- 野澤が、共有された項目の物理名と論理名が食い違っている2行について、「変えたいのは論理名と物理名のどちらか」を確認した。
  - 部署名は、物理名ではブランチネーム。
  - 組織名は、物理名ではディビジョンネーム。
- 坪田によると、ACE側では組織名と呼ばれる項目はすべて100文字である。
- UDS側のDBでは、ディビジョンネーム（営業所属組織名）が110文字である。営業担当者名はACE側が100文字。

## 決定
- ディビジョンネーム（110文字）は、ACE側の100文字より大きいため、修正しない。部署名・組織名はどちらの名称でも問題ない（坪田: 「溢れないんで」）。
- 営業担当者名は100文字で進める。
- ACEの桁数よりUDS側が小さい箇所は、UDS側で修正する。野澤は「UDS側が小さい部分1箇所、2箇所、3箇所、4箇所ですかね。そこだけは回収します」と述べ、4箇所を修正する（Geminiメモでも「4箇所」）。
- ACEとサイズが合っていないその他の箇所は、溢れないため、直しても直さなくてもよい（坪田）。
- これでフォーマット上の問題はない（野澤: 「ここに関しては問題なし」）。

## 理由
- UDS側のカラム長がACE側より小さいと、ACEから連携された値が溢れてしまう。一方、UDS側が同じか大きければ、溢れないため修正は必須ではない。

## 影響・トレードオフ
- UDS側でDBスキーマの修正が必要になる（担当: 野澤）。

## 未解決事項・次のアクション
- [ ] [野澤有沙] UDS側のDBスキーマで、サイズが不足している4箇所を修正する。
- [ ] [野澤有沙] 修正する4箇所の項目名をADRまたは作業記録に記載する（要確認：会議では項目名が読み上げられていない）。

## 補足
- 文字起こしの「部署名が今50なのこれ100にする」は、野澤が現状を確認した発言で、坪田が「はい」と答えている。部署名の現状の桁数がUDS側なのかACE側なのかは文字起こしからは断定できない（要確認）。
- Geminiメモの「ディビジョンネームは110文字、組織名は100文字」は文字起こしと一致しているが、「どちらの名称でも問題ない」の主語が部署名・組織名のどちらを指すかは、文字起こしでは曖昧である。
