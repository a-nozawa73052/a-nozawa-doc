# ADR-0009: com.tsvの更新・挿入の判定キーを契約CD（contract_cd）のみに変更する

- 決定者・関係者: 野澤有沙、佐々木航太（UDS）
- 出典: 文字起こし 00:53:26〜00:56:12（Geminiメモ: https://docs.google.com/document/d/1n-Av2kjhakuFZvuhaYh-807svACt8pbR069ukM9-Nd4）

## コンテキスト
- 現行のcom.tsv（NeOS → UDS）は新規契約時に1回しか連携されない。
- ACE移行後は、プラン変更時にcom.tsvが複数回連携される。品目によって入る値が違い、それがないとアルテリアの解約などの業務が成立しない。
- 現行の判定キーは「契約CD、NeOS親パック品目CD、NeOS品目CD」の3つで、一致するレコードがあればアップデート、なければインサートになる。
- ACE移行後はNeOS親パック品目CDがなくなり、プラン変更で品目CDも変わるため、2回目の連携がインサートになってしまう。

## 決定
- com.tsvのアップデート判定キーを契約CD（contract_cd）のみに変更する。

## 理由
- 現行コードを読む限り、判定キーを崩しても問題はなさそうだった（野澤）。
- 連携が1回のみだった現行では、3つをキーにする理由が分からなかった（佐々木・野澤）。

## 検討した代替案
- 現行の3キーを維持する案 → プラン変更のたびにインサートされるため却下した。

## 未解決事項・次のアクション
- [ ] [野澤] com.tsvのうち、連携不要になる項目の扱い（NULL固定で連携するか、項目ごと削除するか）を決める。会議中は未確定（「どちらかに統一してもらおうかな」）。

## 補足
- ACEからNULL固定で送ってもらう項目と、ファイルから消える項目が混在している。具体的な項目は会議中に確定していない（要確認）。
