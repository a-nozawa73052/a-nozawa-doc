# ADR-0018: PHPのpost_max_sizeをupload_max_filesizeより1MB大きく設定する

- 決定者・関係者: 部屋智洋、森晨滉、野澤有沙（UDS）
- 出典: 文字起こし 00:00:06〜00:09:20（Geminiメモ: https://docs.google.com/document/d/1P7lDzxiJ3AeSJfOtVibopww7ppry9sw6rebAX4_oipg）
- 備考: 設定値は要確認（補足を参照）

## コンテキスト
- 脆弱性対応の一環として、インフラ側（中島さん）から、PHP設定のアップロード関連の値について意見が出ていた（部屋さんが代弁。中島さんは今回不参加）。
- UDS調査時点では、post_max_size と upload_max_filesize が同じ値だった。

## 決定
- post_max_size を upload_max_filesize より1MB大きくする（php.iniの上側の値を+1MBする）。
- 修正は森が行う。

## 理由
- 今回の脆弱性対応で致命的に効くわけではないが、そのほうが安全である（部屋: 「中島さん的にはそのほうが安全じゃないかという意見をもらっている」）。

## 影響・トレードオフ
- 設定変更のみ。影響範囲や副作用は会議では議論されていない。

## 未解決事項・次のアクション
- [ ] [森] php.iniの設定値を修正する。
- [ ] （要確認）変更後の具体的な値と、対象の環境（ステージング／本番）を確認する。

## 補足
- Geminiメモは「アップロード最大ファイルサイズを上方修正し、post_max_sizeを制限値+1MBにする」としているが、文字起こしでは「上の方（post_max_size）をプラス1M」と読める。文字起こしを優先して上記のとおり記載した（要確認）。
- 文字起こしに「21にする」という発言があり、upload_max_filesizeが20MBで、post_max_sizeを21MBにする意味の可能性があるが、確証はない（要確認）。
- 野澤が、関連するスプレッドシートを森に共有した。
