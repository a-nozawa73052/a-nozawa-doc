# ADR-0014: ACE移行で連携されなくなる「明細課金月」を、直送案件の全項目CSVから削除する

- 決定者・関係者: 植田崇、亀山彩乃、桑鶴恵里、坪田亜実、野澤有沙（UDS）
- 出典: 文字起こし 00:00:10〜00:12:36、00:13:51〜00:14:47（Geminiメモ: https://docs.google.com/document/d/1r0JZ0F3huuy2O79xGsDX6WAWXvQmxGnYx0LEHL7p_ac）
- 備考: 文字起こしでは「明細」が「迷彩」「明産」、「直送」が「直走」「直案件」などに誤変換されている。「直案件行目SV」は「直送案件の全項目CSV」と解釈した（要確認）。削除自体は了承されたが、確認業務の代替手段は未定（要確認）。

## コンテキスト
- UDSの直送案件の全項目CSVには「明細課金月」が出力されている。この値は現在NeOSから連携されたものを、UDSがそのまま持っている（坪田）。
- ACE移行後は、ACEから明細課金月が連携されなくなる。このため、CSVからこの項目を削除してよいかを、営業側（植田・亀山・桑鶴）に確認した。
- 営業側は、この項目を次の目的で使っている。
  - 通常は設置月から3ヶ月後に課金が始まるが、翌月や半年後などイレギュラーなものがある。営業が入力した課金月が合っているか、UDSのデータとUNISの確定値をすり合わせて確認している（亀山）。
  - 3ヶ月後課金のところを、誤って翌月で登録してしまう「依頼ミス」の目視確認にも使っている（亀山）。
  - 監査報告で、課金開始月ごとに分けて報告している（桑鶴）。
- 課金月の確認に使えるデータは、現状はUDSからの抽出だけである（亀山）。
- UNISにはすでに明細課金月が入っており、誤りがあれば確定前に修正している（植田）。

## 決定
- 直送案件の全項目CSVから、明細課金月を削除する。植田は削除自体は問題ないと回答した（野澤の説明による。文字起こし 00:01:48）。
- 営業側は、ACEやUDSから課金月が分かるデータを今後取得できれば、項目がなくなっても問題ないとしている（亀山）。代替手段が確保できるかは、下記の未解決事項で確認する。

## 理由
- ACEから明細課金月が連携されなくなるため、UDSでは値を持てない。
- 坪田は、UDSに連携しなくても、ACEから出せれば足りるのではないかと述べた。亀山と桑鶴も、ACEなどから取得できれば問題ないとした。

## 影響・トレードオフ
- 依頼ミスの目視確認、課金月のすり合わせ、監査報告の分類に、UDS以外の手段が必要になる。
- ACEでの課金月の設定や制御の運用は未確定である。ACEでは、サービスに関係なく初期設定やコース変更のラインしか決まっていない（坪田）。ACE側の関係者と話す必要がある。

## 検討した代替案
- 明細の特定は、現行では契約番号と明細番号で行っていると坪田は推測している（要確認）。ACE移行後は、ACEから連携される「提供サービス明細コード」が明細の一意なキーになる（坪田）。ただし、データ抽出して提出する用途などで別の項目が必要なら、洗い出しを依頼するとした。

## 未解決事項・次のアクション
- [ ] [桑鶴恵里] UDSにおける明細課金月の確認業務の現状と課題を、業務マニュアルや一覧の形でまとめ、今月中（来週中）に坪田・野澤へ提出する。
- [ ] [桑鶴恵里] 明細の特定に必要な情報の代替キーを洗い出す。
- [ ] [プロ業側] 明細課金月以外にも、UDSに関わる業務で、ACE移行で項目がなくなると困るものがあれば、早めに坪田・野澤へ共有する（坪田の依頼）。
- [ ] [坪田亜実・野澤有沙] 課金月の設定運用をACEでどう制御するかを、ACE側の関係者と協議する（要確認。会議では担当を明言していない）。

## 補足
- Geminiメモでは、桑鶴の資料提出は「調整済み」、代替手段の検討は「さらなる議論が必要」に分類されている。
- 「依頼ミス」の正確な意味（営業の入力ミスか、プロ業への依頼内容のミスか）は、文字起こしでは「営業が入力した課金月が合っているかの確認」と坪田が言い換えて亀山が肯定している。
