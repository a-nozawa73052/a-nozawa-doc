# ADR-0007: UDSにも提供サービス明細コードを保持し、contract.tsvのカラムとして連携する

- 決定者・関係者: 野澤有沙、佐々木航太（UDS）
- 出典: 文字起こし 00:43:55〜00:46:28（Geminiメモ: https://docs.google.com/document/d/1n-Av2kjhakuFZvuhaYh-807svACt8pbR069ukM9-Nd4）

## コンテキスト
- ACEでは、営業・総務などが見る契約のキーが、NeOS契約コード（契約CD）から「提供サービス明細コード」に変わる見込み（UMEMBERSなどでも見せ方が変わる想定。要確認）。
- UDS内では提供サービス明細コードを処理には使わない。
- 問い合わせの際、共通言語になるのは提供サービス明細コードになりそうである。

## 決定
- UDSにも提供サービス明細コードを持たせる。contract.tsvにカラムを追加して連携してもらう。
- プラン変更が起きるたびに、この値はアップデートが必要になる。

## 理由
- 問い合わせを受けたときに、UDS側でも契約を特定できるようにするため。

## 影響・トレードオフ
- 既存契約には一括で値を入れないため、リリース時点では既存契約のこの値はNULLのままになる（ADR-0002）。そのためカラムはNOT NULLにできない。
- 本番ではACE側で既存契約にも提供サービス明細コードを払い出すが、UDSへ洗い替えはしない。ステージングでは既存契約への払い出し自体を行わない。

## 補足
- 既存契約への一括移行を見送るのは井上の結論（数十万件あり、移行するほうがリスク）と野澤が説明した。問い合わせが来たら都度確認する。
