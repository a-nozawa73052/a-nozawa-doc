# ADR-0022: UDSのセキュリティパッチ適用に向けた、PHP・FuelPHP・DBのバージョンアップとリプレイスの方針

- 関係者: 井上充、森晨滉、稲田翔、野澤有沙、軽部壮真（UDS）
- 出典: 文字起こし 00:01:13〜00:07:32（Geminiメモ: https://docs.google.com/document/d/1a_MPCdVQkfKY1Z0H_I70SgZmD0P0VkqR2fos194u_vk）
- 備考: 工数レポートを出したうえで、上層部が実施可否を判断する

## コンテキスト
- 今回やりたいことは、最短でセキュリティパッチを適用することである（井上）。
- 森の調査では、PHPのバージョンアップだけでは動かない。次の対応が必要になる。
  - FuelPHPフレームワーク本体の更新
  - PDF/Excelのライブラリの置き換え（すでに使われていないもののため）
  - 処理が止まる40箇所への対応
- 森は、移行は実質可能だと報告した。工数は「3.3から5.7月」と聞こえるが、聞き取りにくい（要確認）。そのうち3割が手動の回帰テストである。
- 最大の不確定要素は、FuelPHPの最新版1.9（開発段階で安定版ではない）がPHP 8.5で動くかどうか。安定版は1.8で、PHP 7.4までの対応と聞こえる。
- セキュリティパッチが提供されているのは、PHP 8.5だけだと森は考えている（森: 「8.5しかされてないと思う」。裏付けは未確認で、要確認）。
- データベースも、RDS（Amazon Aurora MySQL）のサポートが切れている。MySQLのメジャーバージョンを1つ上げる必要があり、PHPと同時に行うことになる（井上）。
- 井上は、UDSが外部向けのシステムだったら深刻な状況だと述べた。社内システムでIP制限がかかっているため、今回の対応の中では優先度が低い。

## 選択肢
| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A | FuelPHPを更新し、PHPをバージョンアップする（FuelPHP 1.9＋PHP 8.5など） | 作り直しより小さい工数で済む可能性がある | FuelPHP 1.9が安定版でなく、PHP 8.5で動くか不確定。PDF/Excelのライブラリ置き換えや40箇所の対応が必要 |
| B | 作り直し（リプレイス）。Webフレームワークも変える（CakePHPでもLaravelでもよい） | 脆弱性対応の根本解決になる | 開発工数が大きい。PHPにこだわる必要もない（井上） |
| C | PHPを7.4のまま維持する | 不確定要素が減る | セキュリティパッチが適用できない（森・井上: 「終了」） |

## 判断軸
- 最短でセキュリティパッチを適用できるか。
- 開発工数と、データベースのバージョンアップによる移行工数。
- UDSは社内システムでIP制限がかかっているため、緊急度は低い。外部アクセスを絞る対応で足りるか、開発期間を取るか。

## 現時点の方向性
- 案Cは不可という認識で一致した。
- 案Aと案Bの工数を比較するレポートを出し、そのうえで上層部が実施可否を判断する。

## 未解決事項・次のアクション

- [ ] [森] ①〜③に、データベースのバージョン変更に伴う移行工数も含める（稲田の依頼）。
- [ ] [井上] 中島さん・坂本さんと相談し、外部アクセスを絞るか、開発期間を取るかを判断する。
- [ ] [野澤・井上・軽部] 認識合わせを行い、上層部に判断を仰ぐ。
- [ ] （要確認）森が工数レポートを出す期限。井上は「この後30分〜1時間」と話しているように聞こえるが、聞き取りにくい。

## 補足
- 森の工数見積もりの数値と、「3割が手動の回帰テスト」という内訳は、文字起こしの聞き取り精度が低く、確定できない。
- 同じ週のiPhone接続の設計相談でも、PHPバージョンアップのスケジュールが話題に出ている。
